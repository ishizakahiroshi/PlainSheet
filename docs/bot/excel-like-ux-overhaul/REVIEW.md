# 独立レビュー指示 #20261005-004 Excel 風 UX 刷新

実装担当とは別の担当が、[README.md](README.md) の仕様に対する実差分と失敗経路を確認する。差分の起点は初回指示公開 commit、終点は実 code SHA。

## 確認すること

- 各 C の完了条件（README の C 詳細）が、テストまたは実際の画面操作で満たされているか。テストが無いものは画面の確認結果があるか
- 5 形式（CSV/TSV/Markdown Table/JSON/YAML）と文字コードの読み書き結果が変わっていないか（既存テストが全て通り、保存内容が期待どおりか）
- 列移動・ソート・フィルタの後に保存したファイルの列順・行順が、画面と README の維持条件に一致するか
- Undo/Redo が新しい編集操作（打鍵編集・フィルハンドル・Ctrl+D/R・列移動）で破綻しないか
- 日本語入力の変換確定でセルが移動しないか、確認した方法が書かれているか
- 空の表、1 行 1 列の表、列数が行ごとに違う表、非常に長い文字列のセルで落ちないか
- 日英の翻訳キーが過不足なく揃っているか
- 触ってはいけない範囲（`src-tauri/`、`.github/workflows/`、依存の追加）に変更が入っていないか
- docs と生成物を無関係な差分と誤認しない

## 提出

- レビュー対象の code SHA
- 重大度つきの指摘と再現手順
- 実行した command と結果
- 未検証の範囲

修正後は新しい SHA の影響範囲を再検査する。古い PASS を引き継がない。指摘なしの場合も、確認した範囲を明記する。
